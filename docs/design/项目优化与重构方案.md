## 1. 项目定位

本项目定位为：

> 部署在无法访问互联网的企业内网中，以 Web 为主要入口、CLI 为无浏览器备用入口的单机专业 LLM 性能压测工具。

确定的产品边界：

- 保持纯单机个人工具；
- 部署在 Linux/Docker 服务器；
- Windows 7 仅作为浏览器访问端；
- 保留简单的单账号登录，防止内网无关人员滥用；
- 不建设多用户、角色、多租户、组织、审批和计费系统；
- 不引入 Redis、Celery 或外部数据库；
- Web 是主要操作入口；
- CLI 可在没有浏览器、Web 服务未启动或只需快速测试时独立运行；
- 首期只完善 OpenAI 兼容协议；
- 首期完成专业性能压测，模型能力评测作为后续独立模块。

## 2. 当前实现的主要问题

### 2.1 压测指标准确性

核心文件：`llm_benchmark.py`

当前存在以下风险：

- 流式响应遇到 `finish_reason` 后立即退出，可能错过最后的 `usage` 数据；
- 服务未返回 usage 时，当前使用流式响应块数量作为 Token 数，但分块不等于 Token；
- 当前 TPS 使用“输出 Token ÷ 完整请求耗时”，其中包含 TTFT，不能准确表示生成阶段速度；
- TPS 的 P95、P99 使用反向百分位计算，但界面仍按普通 P95、P99 展示，语义容易误解；
- 只记录成功请求，失败请求没有错误类型、耗时和失败阶段；
- 使用 `time.time()` 测量耗时，应该使用单调高精度时钟；
- HTTP 客户端没有可靠关闭；
- TLS 校验被硬编码为关闭；
- SDK 超时和 `asyncio.wait_for` 双重控制，行为不够清晰；
- 不支持安全停止正在运行的任务；
- 提示词随机抽取但不记录随机种子，结果无法复现；
- 短提示词列表存在缺少逗号的问题，两个问题被意外拼接；
- “短文本/长文本”不能准确表达输入 Token 长度。

上述问题属于最高优先级，必须先于视觉重构解决。

### 2.2 后端任务模型

核心文件：`backend/app.py`

当前问题：

- 所有任务共用一个全局内存字典；
- 任务 ID 固定为 `current`；
- 服务重启后运行状态丢失；
- 后台使用 daemon 线程，进程退出时可能直接中断；
- 没有任务队列、安全停止和阶段状态；
- 梯度档位硬编码为 `1、50、100、200、300`；
- 参数直接执行 `int()`，非法输入可能返回 500；
- `bool("false")` 会得到 `True`，布尔参数解析不可靠；
- 通用异常处理直接把异常文本返回前端；
- CORS 对全部来源开放；
- JWT 永不过期；
- 默认用户名、密码和 JWT 密钥不安全；
- API Key 以明文 JSON 保存；
- 报告以独立文件存在，缺少任务、配置和报告之间的统一索引。

### 2.3 前端结构

当前前端使用 Vue 2、Vue CLI、Element UI 和 ECharts 4。

主要问题：

- 运行状态主要保存在页面组件中；
- 刷新后不能可靠恢复当前任务；
- 只有完成数量轮询，没有实时吞吐、延迟和错误曲线；
- 配置、运行进度和结果集中在一个页面；
- 历史报告只是文件列表，不是可检索的任务记录；
- 没有测试方案、数据集、阈值模板、基线和模型对比概念；
- 页面视觉接近通用管理后台；
- 没有完善的失败恢复、空状态和浏览器兼容提示；
- 缺少前端自动化测试。

## 5. 专业性能测试方案

### 5.1 接口冒烟测试

- 发送 1～3 个请求；
- 检查认证、模型、流式响应、usage 和 finish reason；
- 检查 content、reasoning 字段和响应格式；
- 正式压测前可自动执行；
- 避免配置错误导致整轮测试失败。

### 5.2 基线延迟测试

- 并发固定为 1；
- 支持预热请求；
- 预热数据不进入正式统计；
- 测量单请求性能上限；
- 用于版本和模型之间的基础对比。

### 5.3 固定并发负载测试

支持两种结束条件：

- 完成固定请求数；
- 持续固定时间。

用于验证明确业务负载下的吞吐与稳定性。

### 5.4 阶梯容量测试

- 并发档位可编辑；
- 支持预热、测量和冷却；
- 自动检测吞吐、延迟和错误率拐点；
- 达到保护阈值后可以自动停止；
- 给出建议工作并发区间和极限并发；
- 不生成不透明的综合性能评分。

### 5.5 恒定到达率测试

- 用户指定目标 QPS；
- 请求按照节奏进入；
- 区分目标 QPS、实际发送 QPS和完成 RPS；
- 统计排队、积压、丢弃和超时；
- 用于模拟真实业务到达率。

### 5.6 稳定性测试

- 按固定负载持续运行；
- 按时间窗口展示吞吐、延迟和错误率；
- 检测后半程吞吐下降和延迟漂移；
- 支持最大请求数和全局安全限制。

输入上下文长度、期望输出长度和提示词类型作为各测试方案的变量，不再使用简单的“是否启用长文本”开关。

## 6. 指标体系

### 6.1 请求级指标

- 请求排队时间；
- 建连与首响应时间；
- TTFT；
- 端到端延迟；
- 生成阶段持续时间；
- 输入、输出和总 Token；
- 单请求输出 Token/s；
- HTTP 状态；
- finish reason；
- 错误分类；
- 响应断言结果。

### 6.2 任务级指标

- 总尝试请求数；
- 协议成功率；
- 有效响应率；
- 断言通过率；
- 成功完成 RPS；
- 目标与实际到达率；
- 服务整体输入 TPS；
- 服务整体输出 TPS；
- 活跃、排队和在途请求；
- P50、P90、P95、P99、最小值、最大值、平均值和标准差；
- 按时间窗口划分的吞吐、延迟和错误率；
- 预热、正式测量和冷却阶段的独立统计。

### 6.3 Token 统计原则

- 优先使用服务端 `usage`；
- 本地 tokenizer 只能作为估算；
- 估算值必须明确标记；
- 禁止使用流式分块数代替 Token 数；
- 推理 Token、可见输出 Token和总输出 Token在服务支持时分开记录；
- 无法精确统计时显示“不支持”或“估算”。

## 8. 响应有效性检查

首期支持确定性断言：

- 内容非空；
- 输出 Token 范围；
- finish reason；
- 包含或不包含指定文本；
- 正则表达式；
- 精确匹配；
- JSON 可解析；
- JSON Schema 校验；
- 响应字段完整性。

结果拆分为：

- 请求成功率；
- 有效响应率；
- 断言通过率。

首期不加入 LLM-as-a-Judge。模型能力评测和权威跑分作为后续独立模块开发，不与性能压测实时路径耦合。

## 9. 阈值和历史基线

使用“逐项阈值判定＋历史基线对比”，不生成单一综合分。

指标状态：

- 通过；
- 关注；
- 未通过；
- 无判定。

阈值示例：

- 成功率不低于指定值；
- TTFT P95 不高于指定值；
- 端到端延迟 P95 不高于指定值；
- 整体输出 TPS 不低于指定值；
- 实际 QPS 达到目标 QPS 的指定比例；
- 超时率不高于指定值；
- 稳定性后半段吞吐下降不超过指定比例。

历史基线对比显示：

- 吞吐变化；
- TTFT 和端到端延迟变化；
- P95、P99 变化；
- 错误率变化；
- 输入和输出 Token 差异；
- 配置是否具备可比性；
- 性能回退项和改善项。

## 10. 任务执行模型

### 10.1 默认策略

- 可以创建和排队多个任务；
- 默认同一时间只运行一个任务；
- 当前任务完成、失败或停止后再执行下一项；
- 阶梯测试中的多个档位属于同一任务；
- 支持立即安全停止；
- 首期不实现暂停后续跑。

### 10.2 浏览器和服务重启

- 关闭浏览器、退出登录或更换浏览器不停止任务；
- 重新打开页面后恢复当前任务和实时数据；
- 前端补取断线期间的时间序列；
- 服务进程重启后，运行任务标记为异常中断；
- 保存已完成请求和阶段数据；
- 中断任务不自动续跑；
- 排队但尚未开始的任务在重启后等待用户确认。

### 10.3 模型对比

支持：

- 多模型串行对比；
- 可选同步对比；
- 每个模型独立设置负载；
- 总负载按所有模型累加；
- 同地址同步运行时提示共享资源风险；
- 区分独立服务同步对比与共享资源竞争测试；
- 同步与串行结果不默认混合排名。

## 11. 安全护栏

默认启用可配置软限制：

- 最大并发；
- 最大目标 QPS；
- 最长持续时间；
- 最大请求数；
- 测试前负载预估；
- 高风险参数二次确认；
- 始终可见的停止按钮；
- 错误率、延迟、积压和压测机负载自动停止条件；
- 预热和档位间冷却；
- 不对失败请求自动重试；
- 压测机 CPU、内存、网络连接和事件循环延迟监控；
- 允许高级用户明确确认后突破软限制。

## 13. 前端视觉设计

### 13.1 色彩

- 陶瓷灰白：`#F3F6F6`；
- 石墨灰：`#263840`；

- 安全琥珀：`#D99022`；

### 13.2 字体

- 中文正文优先使用 `Microsoft YaHei`；
- 通用正文回退到 `Segoe UI`、Arial；
- 数字、Token、延迟和日志使用 Consolas 等宽字体；

### 13.3 标志性元素

使用“负载轨迹尺”表达测试阶段：

```text
连接检查 → 预热 → 并发 5 → 冷却 → 并发 10 → 并发 20
                         ▲ 当前阶段        ⚠ 延迟接近阈值
```

轨迹尺同时表达：

- 当前测试阶段；
- 并发或 QPS 变化；
- 性能拐点；
- 用户停止或自动保护位置。

避免：

- 通用 Element UI 管理后台观感；
- 大量无意义卡片；
- 全屏深色黑客风格；
- 大面积渐变和发光边框；
- 无用途的分散动画。

- 应用日志。

默认保留原则：

- 汇总结果长期保留；
- 逐请求明细提供可配置保留策略；
- 页面显示磁盘占用；
- 不在后台静默删除报告。

## 17. 旧数据迁移

当前数据情况：

- `backend/api_configs.json` 中有 1 条配置；
- `reports/` 中有 9 个结构一致、可解析的 JSON 报告；
- 另有 6 个 XLSX 和 4 个 CSV。

迁移策略：

- 首次启动时检查旧配置和报告；
- 有效配置导入 SQLite；
- API Key 导入后使用本地密钥加密；
- 扫描旧 JSON 报告并生成任务索引；
- XLSX、CSV 作为已有导出文件关联；
- 旧报告标记为“不包含逐请求明细”；
- 原文件不移动、不删除、不修改；
- 单文件导入失败不影响其他文件；
- 迁移失败不阻止应用启动；
- 页面显示迁移失败文件和原因；
- 支持手动重新扫描；
- 使用路径和内容哈希去重；
- 可以通过环境变量跳过迁移。

## 19. CLI

CLI 可以在 FastAPI/Web 未启动时独立完成压测，直接调用共享核心。

建议命令：

```text
llm-benchmark smoke
llm-benchmark run
llm-benchmark compare
llm-benchmark task list
llm-benchmark task show
llm-benchmark report export
```

CLI 要求：

- 支持六类性能测试方案；
- 支持 YAML/JSON 方案文件；
- 支持 JSONL 数据集；
- 支持阈值判定；
- 支持串行和同步模型对比；
- 支持终端实时进度；
- 支持 `Ctrl+C` 安全停止；
- 支持人类可读摘要和机器可读 JSON；
- 测试结果写入相同的 SQLite 和报告目录；
- Web 与 CLI 使用文件锁避免冲突运行；
- API Key 优先通过环境变量或交互式隐藏输入获取；
- SQLite 暂时不可写时允许通过 `--output result.json` 保存结果。

旧版 `webui.py` 最终删除，避免维护第二套 GUI。

## 20. 完全离线部署

目标环境从部署开始就无法访问互联网。

部署前提：

- 目标 Linux 服务器已经安装 Docker Engine；
- 已经安装 Docker Compose；
- 应用通过预构建 Docker 镜像归档交付。

离线部署包：

```text
llm-benchmark-offline-<version>/
├── images/
│   └── llm-benchmark-<version>.tar
├── docker-compose.yml
├── .env.example
├── scripts/
│   ├── install.sh
│   ├── run.sh
│   ├── stop.sh
│   └── update.sh
├── docs/
│   ├── 离线部署说明.md
│   ├── CLI使用说明.md
│   └── 常见问题.md
├── checksums.sha256
└── VERSION
```

### 20.1 install.sh

- 检查 Docker 和 Docker Compose；
- 校验镜像文件 SHA-256；
- 加载离线镜像；
- 创建数据目录；
- 从 `.env.example` 生成 `.env`；
- 提示修改登录密码和应用密钥；
- 不自动启动服务。

### 20.2 run.sh

- 校验必要配置；
- 启动容器；
- 等待健康检查；
- 显示访问地址、容器状态和日志查看命令。

### 20.3 stop.sh

- 停止应用；
- 不删除容器数据；
- 不执行 `docker compose down -v`。

### 20.4 update.sh

- 校验新版离线镜像；
- 备份 SQLite 数据库和关键配置；
- 记录当前镜像版本；
- 加载并启动新镜像；
- 执行数据库迁移；
- 等待健康检查；
- 失败时停止新版容器；
- 恢复数据库备份；
- 恢复旧镜像版本；
- 重新启动旧版本；
- 输出失败原因和日志位置。

部署和运行期间不得执行：

- `docker pull`；
- `docker compose build`；
- `npm install`；
- `pip install`；
- `apt-get`；
- 在线下载字体、前端资源或数据集。
