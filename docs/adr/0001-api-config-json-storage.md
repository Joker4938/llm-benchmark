# ADR-0001: 使用后端 JSON 文件持久化存储 API 配置

## 状态
已接受

## 背景
用户需要在 LLM-Benchmark 中保存多组 API 接口设置（Base URL、API Key、Model），并在发起压测时快速选择使用哪一组。当前系统仅通过浏览器 localStorage 保存单一配置，无法支持多配置管理，且配置无法跨设备共享。

## 决策
采用服务器端 JSON 文件作为 API 配置的持久化存储介质，通过 Flask REST API 提供增删改查能力。

## 权衡考虑的替代方案

1. **继续用 localStorage**
   - 优点：实现最简单，无需后端改动。
   - 缺点：配置绑定到单个浏览器，换设备/清缓存即丢失；无法与"选择配置"的后端语义良好配合。

2. **引入 SQLite / 关系型数据库**
   - 优点：支持更复杂的查询和事务。
   - 缺点：当前项目为零依赖（除 Flask 外无数据库），引入 SQLite 会增加部署复杂度和容器体积，且配置数据量极小（预计 <100 条），用数据库属于过度设计。

3. **后端 JSON 文件（选中方案）**
   - 优点：与项目极简风格一致；无需新增依赖；文件可直接版本控制或挂载为 Docker Volume；单用户场景下并发极低。
   - 缺点：需要手动处理文件并发读写锁；不具备数据库的 ACID 保证。

## 后果

- 新增 `backend/api_configs.json` 文件存储配置数组。
- 后端需实现配置 CRUD 的 REST API，并在文件读写时加 `threading.Lock` 防止并发损坏。
- 配置可随项目目录持久化（本地）或作为 Docker Volume 挂载（容器化）。
- 未来如需迁移到数据库，JSON 的结构可无损导入。
