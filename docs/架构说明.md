# 系统架构说明

本文描述 LLM Benchmark 重构后的运行架构、模块边界、关键数据流和设计约束。当前系统只面向 **OpenAI Chat Completions 兼容接口的性能压测**；模型能力权威评测属于后续独立模块，不与性能压测结论混合。

## 1. 架构目标

系统围绕以下约束设计：

- 纯单机个人工具，不依赖 Redis、Celery、外部数据库或云服务；
- Web 为主要操作界面，CLI 在无浏览器环境中仍可完成完整压测；
- Web 与 CLI 必须共享同一套协议、调度、指标和报告语义；
- 默认同一时间只运行一个压测任务，防止负载无意叠加；
- 同步模型比较必须显式确认，并清楚显示总负载和资源竞争语义；
- 部署和运行环境可以完全无法访问互联网；
- Windows 7 只作为浏览器客户端，不作为服务端运行环境；
- 登录保持简单，只用于降低内网无关人员误用或滥用的风险。

## 2. 总体结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 浏览器：Vue 3 / Pinia / Vue Router                           │
│ 登录、工作台、实时运行、历史记录、资源、设置与诊断             │
└───────────────────────────────┬──────────────────────────────┘
                                │ HTTP / SSE
                                ▼
┌──────────────────────────────────────────────────────────────┐
│ FastAPI                                                       │
│ 认证、输入校验、安全预检、任务/比较/报告 API、静态页面托管       │
└──────────────┬───────────────────────────────┬───────────────┘
               │ 持久化任务与事件                  │ 查询/导出
               ▼                                  ▼
┌──────────────────────────┐       ┌───────────────────────────┐
│ SQLite + Repository      │       │ 本地报告目录               │
│ 配置、队列、状态、事件、索引 │       │ JSON/JSONL/HTML/CSV/XLSX │
└──────────────┬───────────┘       └───────────────────────────┘
               │ 领取任务、心跳、完成状态
               ▼
┌──────────────────────────────────────────────────────────────┐
│ Local Executor                                               │
│ 默认单任务；同步比较时一次领取同一比较组并并发执行              │
└───────────────────────────────┬──────────────────────────────┘
                                │ 调用共享核心
                                ▼
┌──────────────────────────────────────────────────────────────┐
│ benchmark_core                                               │
│ OpenAI 客户端、工作负载、计划调度、窗口指标、断言、阈值、报告   │
└───────────────────────────────┬──────────────────────────────┘
                                │ /v1/chat/completions
                                ▼
                       OpenAI 兼容模型端点

独立 CLI ───────────────────────► benchmark_core ───────────────► 模型端点
```

Web 路径通过 SQLite 持久队列解耦提交和执行；CLI 路径直接调用 `benchmark_core`，不要求 FastAPI、SQLite、浏览器或 executor 正在运行。

## 3. 代码模块

### 3.1 `benchmark_core/`

压测领域核心，不依赖 Web 框架。主要职责：

- `client.py`：OpenAI Chat Completions 兼容请求、流式解析、协议错误分类；
- `models.py`：计划、请求、结果和取消信号等领域模型；
- `scheduler.py`：六类计划调度、阶段控制、并发/到达率、预热和冷却；
- `workloads.py`：内置负载、自定义消息、JSONL 数据集、种子和顺序快照；
- `validation.py`：确定性响应断言；
- `windows.py`：持续时间窗口聚合；
- `autostop.py`：基于错误率、P95、排队和发生器资源的自动停止；
- `thresholds.py`：完成后阈值和历史基线比较；
- `stats.py`、`summary.py`、`tokens.py`：统计、摘要和 Token 来源处理；
- `reporting.py`：版本化摘要和报告基础写入；
- `redaction.py`：日志、错误和结果脱敏。

核心层只关心“如何执行和解释一次压测”，不负责登录、HTTP 路由、数据库队列或页面状态。

### 3.2 `benchmark_cli/`

独立 CLI 适配层，提供：

- `run`：运行单目标压测；
- `compare`：顺序或显式确认后的同步模型比较；
- `validate-dataset`：离线校验 JSONL 数据集；
- `diagnose`：离线环境和目标连接诊断。

CLI 负责参数、环境变量、JSON 配置、终端输出和稳定退出码，然后把标准化后的配置交给 `benchmark_core`。详细命令见 [CLI 使用说明](CLI使用说明.md)。

### 3.3 `benchmark_server/`

Web 服务端和本地执行器：

- `api.py`：FastAPI 应用工厂、Pydantic 输入模型、认证依赖、业务 API、SSE、报告下载和 Vue 静态文件托管；
- `database.py`：SQLite 连接、WAL、迁移、事务和数据库容错恢复；
- `storage.py`：Repository，封装配置、数据集、模板、队列、事件、比较和报告索引；
- `executor.py`：持久队列消费者、心跳、取消、事件批量写入和任务终态；
- `runner.py`：把持久化任务 payload 转换为 `benchmark_core` 调用并写报告；
- `auth.py`：短期签名会话；
- `security.py`：本地 API Key 加密和密钥文件管理；
- `migration.py`：旧 API 配置和旧报告的幂等迁移；
- `container_main.py`：容器内 API/executor 双进程 supervisor；
- `main.py`、`executor_main.py`：API 和 executor 独立开发入口。

### 3.4 `frontend/`

Vue 3 单页应用：

- `views/`：登录、工作台、运行详情、历史记录、资源和设置；
- `components/`：应用框架、负载轨迹标尺、指标读数和状态提示；
- `api/client.js`：统一 `fetch` 请求、同源 Cookie 和错误模型；
- `stores/`：Pinia 会话与任务状态；
- `router/`：Hash 路由和登录守卫；
- `styles.css`：本地设计令牌、布局、响应式和 reduced-motion 规则。

生产构建输出到 `frontend/dist/`，由 FastAPI 同源托管。前端不使用 CDN、公网字体或运行时包下载。

## 4. 进程模型

### 4.1 生产容器

生产镜像以 `benchmark_server.container_main` 作为容器入口。supervisor 启动两个子进程：

```text
容器 PID 1 supervisor
├── FastAPI / Uvicorn
└── Local Executor
```

设计原因：

- API 不直接执行长时间压测，避免阻塞 Web 请求和健康检查；
- executor 可独立轮询持久队列并记录心跳；
- 任一子进程异常退出时 supervisor 退出，让 Docker 重启策略恢复整个服务；
- 容器收到 TERM/INT 后，supervisor 先向子进程发送终止信号，宽限期结束后才强制结束。

这仍是单容器、单机部署，不引入分布式调度。

### 4.2 本地开发

开发时可分别运行：

```bash
python3 -m benchmark_server.executor_main
python3 -m uvicorn benchmark_server.main:app --host 127.0.0.1 --port 8080
```

两个进程必须指向同一个 `LLM_BENCHMARK_DATA_DIR`，否则 API 创建的任务不会被 executor 看到。

## 5. 数据存储

### 5.1 SQLite

默认数据库文件为：

```text
/app/data/llm-benchmark.db
```

数据库启用：

- foreign keys；
- WAL journal；
- `synchronous=NORMAL`；
- 30 秒 busy timeout；
- 短事务和需要竞争控制时的 immediate transaction。

SQLite 保存：

- 应用设置；
- API 配置及 API Key 密文；
- 数据集、计划模板和阈值模板；
- 任务 payload、优先级、状态、领取令牌和心跳；
- 批量事件；
- 历史基线关系；
- 模型比较及子任务关系；
- 报告元数据、路径、大小和 SHA-256；
- 旧数据迁移记录。

### 5.2 为什么大数据不全部进入 SQLite

逐请求样本和长时间序列可能显著放大数据库体积与锁竞争。因此：

- 队列状态、摘要、索引和适量实时事件进入 SQLite；
- 完整样本和时间序列写入压缩 JSONL；
- HTML、CSV、XLSX 等制品写入本地报告目录；
- SQLite 只保存报告索引和校验信息。

### 5.3 本地密钥

API Key 保存前由 `SecretBox` 加密并附带完整性校验。若未显式提供密钥，服务在数据目录生成 `secret.key`，权限限制为 `600`。

该机制用于防止数据库被单独复制后直接看到明文，以及降低普通文件误泄露风险；它不能防御已经取得服务器或容器完全权限的攻击者。数据库、密钥文件和 `.env` 必须作为同等级敏感数据保护。

## 6. Web 请求与认证

### 6.1 登录流程

```text
浏览器 POST /api/auth/login
        │
        ▼
FastAPI 恒定时间比较用户名和密码
        │
        ▼
签发带到期时间的 HMAC 会话
        │
        ▼
HttpOnly + SameSite=Strict Cookie
```

- 会话默认 12 小时；
- Cookie 不暴露给前端 JavaScript；
- HTTPS 反向代理场景启用 Secure Cookie；
- 登出删除 Cookie；
- 页面路由守卫会先请求 `/api/auth/verify`；
- 认证失败统一返回结构化中文错误。

这是内网防误用的简单登录，不包含注册、角色、团队、多租户或外部身份提供商。

### 6.2 API 校验与异常

Pydantic 模型负责类型、长度、范围和交叉字段校验；业务层继续检查计划安全限制、资源存在性、报告路径和状态转换。

API 将校验错误、HTTP 错误和内部异常转换为稳定错误结构。内部异常只记录脱敏信息，响应不返回堆栈、API Key、会话密钥或文件系统敏感细节。

### 6.3 静态页面

FastAPI 托管构建后的 `frontend/dist/`：

- `/assets/...` 只允许访问前端根目录内的文件；
- SPA 路由回退到 `index.html`；
- API 与页面同源，Cookie 不需要跨域暴露；
- 开发环境可显式配置有限 CORS origin，生产默认不开放任意来源。

## 7. 任务生命周期

### 7.1 普通任务

```text
preflight → queued → running → completed
                        ├──────→ failed
                        ├──────→ stopping → cancelled
                        └──────→ interrupted
```

1. 前端或调用方先提交安全预检；
2. API 验证目标配置、计划、数据集、断言、阈值和硬上限；
3. API 将标准化 payload 持久化为 `queued`；
4. executor 使用原子事务领取任务并生成 claim token；
5. runner 调用 `benchmark_core`；
6. executor 批量写事件、定期更新任务和自身心跳；
7. 完成后写入脱敏结果和报告索引；
8. 取消请求先把状态设为 `stopping`，executor 通过协作式取消安全收尾。

进程重启后，executor 会恢复遗留的中断任务状态，避免任务永久停留在假运行状态。

### 7.2 默认单任务互斥

Repository 默认一次只领取一个普通任务。这样做可避免：

- 单机 CPU、内存、连接数和事件循环先成为瓶颈；
- 多个用户操作无意叠加目标模型负载；
- 相互干扰导致不同测试的性能结论不可解释。

任务可以继续进入持久队列，但在前一个任务结束前不会同时执行。

## 8. 模型比较

### 8.1 顺序比较

顺序比较是默认模式。每个模型使用相同的：

- 数据集内容和 SHA-256；
- 随机种子；
- 实际样本顺序；
- 计划与断言；
- 指标和报告版本。

模型逐个执行，更适合共享发生器或共享模型资源时获得易解释结果。

### 8.2 同步比较

同步比较必须由用户显式选择并确认风险。Repository 将同一比较组的子任务作为一个批次领取，executor 通过 `asyncio.gather` 并发执行这些子任务。

报告和页面必须同时展示：

- 每个模型自身并发或 QPS；
- 所有模型的聚合并发或聚合 QPS；
- `independent` 或 `shared` 资源语义；
- 共享资源竞争可能影响结果的提示。

同步比较是受控例外，不改变普通任务默认单任务互斥规则。

## 9. 实时事件、SSE 与轮询回退

### 9.1 事件链路

```text
benchmark_core 事件
      │
      ▼
executor 内存批次
      │ 达到批量大小或任务阶段结束
      ▼
SQLite task_events（递增 sequence）
      │
      ├──► SSE /api/tasks/{id}/events
      └──► 状态查询 /api/tasks/{id}/status
```

SSE 连接使用事件 sequence 作为续传位置。断线重连后，客户端可从最后已接收序号继续读取，避免把临时网络中断误当成任务中断。

### 9.2 浏览器回退

运行详情页优先使用 `EventSource`：

1. 建立 SSE；
2. 断线时进入有限重连状态；
3. 浏览器没有 `EventSource`，或持续无法恢复时，切换为约 2 秒一次的状态轮询；
4. 页面明确显示当前传输模式；
5. 任务进入终态后关闭连接和定时器。

因此实时连接失败不会影响后台压测执行，也不会让用户失去最终状态。

## 10. 报告与基线

runner 在任务目录写入版本化结果：

- JSON 摘要；
- gzip JSONL 请求样本；
- gzip JSONL 时间序列/事件；
- 自包含离线 HTML；
- 按需 CSV 和 XLSX。

报告生成遵循以下原则：

- 路径必须限制在报告根目录内；
- 文件记录 SHA-256 和大小；
- HTML 不引用 CDN、远程脚本或字体；
- 导出前执行脱敏检查；
- API 下载时重新解析安全路径，不接受任意文件路径；
- 历史基线先判断计划、指标和数据集兼容性，再计算绝对值和百分比变化；
- 不可计算的指标保持 `unavailable`，不以零或估算值伪装。

## 11. 阈值与自动停止

系统区分两类控制：

- **完成后阈值**：任务完成后评估成功率、P95、TTFT、吞吐等指标，用于 CI/CLI 退出码和结果判定；
- **持续窗口自动停止**：任务运行中连续观察多个窗口，在错误率、P95、排队、发生器 CPU/内存或事件循环延迟持续越界时协作式停止。

单个瞬时尖峰不会立即结束任务。触发后，结果记录触发指标、阈值、持续窗口和停止原因，便于判断是目标模型问题还是负载发生器先饱和。

## 12. 健康检查与诊断

服务提供：

- `/health/live`：API 进程存活；
- `/health/ready`：数据库、数据目录和 executor 心跳等就绪条件；
- `/api/diagnostics`：登录后查看版本、平台、数据目录可写性、executor 心跳、生成器资源等诊断信息。

Compose healthcheck 使用 `/health/ready`，因此仅 API 端口可连接但 executor 已失联时，不会被错误判定为完整可用。

## 13. 完全离线运行

离线约束贯穿构建和运行：

- 前端依赖在构建环境锁定并打入镜像；
- Python 生产依赖在构建环境安装并打入镜像；
- 目标服务器只执行 `docker load`，Compose 设置 `pull_policy: never`；
- 页面资源、字体和报告资源全部本地提供；
- 更新备份和数据库迁移容器使用 `--network none`；
- 不使用遥测、外部身份服务或云存储；
- 唯一业务网络访问是管理员明确配置的 OpenAI 兼容模型端点。

详细部署流程见 [完全离线部署说明](离线部署说明.md)。

## 14. 浏览器兼容策略

前端构建目标为：

- Chrome 80 及以上；
- Firefox 78 及以上；
- 重点验收 Windows 7 上的 Chrome 109 和 Firefox 115 ESR；
- 1366 × 768 作为关键桌面分辨率；
- 不支持 Internet Explorer。

路由使用 Hash history，降低内网反向代理和旧服务器路径重写配置成本。关键交互保持原生 `fetch`、表单和可回退机制；SSE 不可用时使用轮询。

## 15. 安全边界

系统提供的保护：

- 简单登录和有限时会话；
- HttpOnly、SameSite Cookie；
- API Key 本地加密；
- 输入、路径和状态转换校验；
- 日志、错误、事件和报告脱敏；
- 容器降权、安全选项和日志滚动；
- 高风险计划与同步比较显式确认；
- 默认单任务互斥和安全硬上限。

系统不试图提供：

- 多租户隔离和细粒度 RBAC；
- 对拥有宿主机 root 权限的攻击者防护；
- 公网暴露所需的 WAF、集中身份认证或证书管理；
- 分布式负载发生器的一致性和容错；
- 模型输出内容的权威能力评分。

如果需要跨团队、公网或强合规部署，应在当前单机工具之外增加网络隔离、HTTPS 反向代理、集中身份认证、审计和独立密钥管理。

## 16. 扩展原则

后续改动应保持以下依赖方向：

```text
frontend ─► FastAPI API ─► Repository / runner ─► benchmark_core
CLI ───────────────────────────────────────────► benchmark_core
```

- 新协议或指标语义先进入 `benchmark_core`，再由 CLI/Web 适配；
- `benchmark_core` 不反向依赖 FastAPI、Vue 或 SQLite；
- 页面不得自行计算另一套压测指标，只展示服务端标准结果；
- executor 不承担页面会话或 HTTP 响应职责；
- 大体积样本优先使用版本化文件制品，而不是不断扩大数据库事件表；
- 模型能力评测未来作为独立模块接入，不能把主观评分混入性能阈值。
